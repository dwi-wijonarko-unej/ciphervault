Dokumen ini mengatur bagaimana CipherVault mendeteksi, merespons, dan mengomunikasikan insiden keamanan yang berpotensi membahayakan data pribadi, sesuai UU PDP No. 27/2022 Pasal 46 yang mewajibkan notifikasi pemegang data paling lambat 3 x 24 jam sejak diketahui.

1. Komitmen Keamanan

Kami merancang CipherVault dengan asumsi bahwa setiap data adalah target. Semua file dienkripsi (UHC + AES cascade) sebelum disimpan, sehingga insiden kebocoran storage tidak otomatis mengungkap plaintext. Meski demikian, kami siap merespons bila terjadi pelanggaran.

2. Definisi Data Breach

Pelanggaran data pribadi (personal data breach) adalah kejadian yang menyebabkan data terungkap, diakses tanpa izin, hilang, atau diubah, baik akibat kesalahan teknis maupun tindakan berbahaya. Contoh:

  • Akses tidak sah ke database atau storage (mis. eksploitasi kerentanan).
  • Kebocoran kredensial admin atau kunci enkripsi global.
  • Hilangnya perangkat atau media cadangan.
  • Serangan denial-of-service yang menyebabkan kebocoran informasi sebagai efek samping.

3. Alur Respons Insiden

1. Deteksi

Pemantauan log aktivitas, anomali traffic, dan laporan pengguna/internal.

2. Penilaian

Klasifikasi tingkat keparahan: cakupan data, kemungkinan eksploitasi.

3. Kontainment

Isolasi sistem terdampak, rotasi kunci, pencabutan token & API key yang dicurigai.

4. Notifikasi

Mengomunikasikan kepada pengguna terdampak dan otoritas bila diwajibkan.

4. Timeline Notifikasi

  • H+0 — Diketahui: tim mulai investigasi dan kontainment.
  • Dalam 72 jam (3 x 24 jam): notifikasi awal kepada pengguna terdampak memuat sifat pelanggaran dan data yang terkena, sesuai UU PDP.
  • Berkelanjutan: pembaruan informasi seiring perkembangan investigasi.

5. Cara Melaporkan Insiden

Jika Anda menduga adanya insiden keamanan (mis. akun Anda diakses tanpa izin), segera laporkan:

  • Email: security@ciphervault.io
  • Subjek: [INSIDEN] + ringkasan singkat.
  • Sertakan: waktu kejadian, bukti (screenshot/log), dan akun yang terdampak.

Kami juga mendorong Anda melakukan responsible disclosure atas kerentanan yang Anda temukan sebelum dipublikasikan.

6. Informasi kepada Pengguna Terdampak

Notifikasi kepada Anda akan memuat, semampu kami tanpa memperburuk situasi:

  • Sifat pelanggaran dan kategori data yang terkena.
  • Estimasi dampak dan langkah yang sedang kami ambil.
  • Rekomendasi tindakan Anda (mis. ganti password, cabut API Key).
  • Titik kontak untuk pertanyaan lanjutan.

7. Tindakan Pasca-Insiden

  • Post-mortem: analisis akar masalah (root cause analysis).
  • Perbaikan: menambal kerentanan, memperketat kontrol akses.
  • Audit: verifikasi integritas data tersisa via SHA-256.
  • Dokumentasi: mencatat pelajaran untuk meningkatkan prosedur.

8. Pengecualian (Bukan Breach)

  • Akses sah oleh admin dalam tugas operasional (tidak menampilkan plaintext).
  • Gangguan layanan tanpa kebocoran data (lihat SLA).
  • Perilaku yang diakibatkan kesalahan konfigurasi pengguna sendiri.

This document governs how CipherVault detects, responds to, and communicates security incidents that may compromise personal data, in compliance with UU PDP No. 27/2022 Article 46 which requires data controllers to notify no later than 72 hours from discovery.

1. Security Commitment

We designed CipherVault with the assumption that every piece of data is a target. All files are encrypted (UHC + AES cascade) before storage, so a storage breach does not automatically expose plaintext. Nonetheless, we are prepared to respond when a breach occurs.

2. Data Breach Definition

A personal data breach is an incident that leads to data being disclosed, accessed without authorization, lost, or altered, whether due to technical error or malicious action. Examples include:

  • Unauthorized access to databases or storage (e.g., vulnerability exploitation).
  • Leakage of admin credentials or global encryption keys.
  • Loss of devices or backup media.
  • Denial-of-service attacks that result in information leakage as a side effect.

3. Incident Response Flow

1. Detection

Monitoring of activity logs, traffic anomalies, and user/internal reports.

2. Assessment

Severity classification: data scope, likelihood of exploitation.

3. Containment

Isolate affected systems, rotate keys, revoke suspected tokens & API keys.

4. Notification

Communicate to affected users and authorities when required.

4. Notification Timeline

  • Day+0 — Discovered: team begins investigation and containment.
  • Within 72 hours (3 × 24 hours): initial notification to affected users detailing the nature of the breach and data involved, per UU PDP.
  • Ongoing: information updates as the investigation progresses.

5. How to Report an Incident

If you suspect a security incident (e.g., your account was accessed without authorization), report it immediately:

  • Email: security@ciphervault.io
  • Subject: [INCIDENT] + brief summary.
  • Include: time of occurrence, evidence (screenshot/log), and affected account.

We also encourage responsible disclosure of any vulnerabilities you discover before they are published.

6. Information for Affected Users

Notifications to you will include, as much as we can without exacerbating the situation:

  • Nature of the breach and categories of data affected.
  • Estimated impact and steps we are taking.
  • Recommended actions (e.g., change password, revoke API Key).
  • Contact point for further inquiries.

7. Post-Incident Actions

  • Post-mortem: root cause analysis.
  • Remediation: patching vulnerabilities, tightening access controls.
  • Audit: verifying integrity of remaining data via SHA-256.
  • Documentation: recording lessons learned to improve procedures.

8. Exclusions (Not a Breach)

  • Legitimate admin access during operational duties (does not expose plaintext).
  • Service disruptions without data leakage (see SLA).
  • Issues caused by user misconfiguration.
